# Измерение скорости загрузки

Консольный скрипт для Node.js 10 раз скачивает файл по указанному URL. Каждый следующий GET начинается после полного чтения предыдущего ответа. В конце скрипт показывает среднее время запроса, общий объём и скорость скачивания.

## Быстрая проверка без интернета

Понадобится Node.js 22 или новее. Скрипт и тесты используют только встроенные модули. Откройте терминал в папке с `download-speed.mjs` и выполните одну команду.

```sh
node --test
```

Тест сам поднимет временный HTTP-сервер на вашем компьютере, запустит настоящий CLI и закроет сервер. В выводе появятся три строки измерения. Ожидаемый объём для первого сценария — **152 895 байт**. Время и скорость зависят от компьютера. В конце отчёта должны пройти все **7 тестов**.

Если у вас ещё нет копии проекта, скачайте и распакуйте архив репозитория или выполните команды ниже, затем запустите тесты.

```sh
git clone https://github.com/Serezjjja/download-speed-cli.git
cd download-speed-cli
```

## Замер для своего файла

Передайте один конечный HTTP- или HTTPS-адрес. Кавычки позволяют передавать ссылки с параметрами, например с символом `&`.

```sh
node download-speed.mjs "https://nodejs.org/static/logos/nodejsLight.svg"
```

При одном из запусков на Node.js 26.13.1 LTS скрипт вывел следующие значения.

```text
Среднее время запроса: 119.23 мс
Всего скачано: 58440 байт
Скорость скачивания: 0.047 МиБ/с
```

## Как читать результат

| Показатель | Что измеряется |
| --- | --- |
| Среднее время, мс | Сумма длительностей запросов, делённая на 10. Каждый замер начинается перед GET и заканчивается после чтения всего тела. |
| Всего скачано, байт | Сумма размеров полученных блоков тела без HTTP-заголовков. Если сервер применил gzip, учитывается размер сжатого тела. |
| Скорость, МиБ/с | Общий объём в байтах / 1 048 576 / суммарное время запросов в секундах. Один мебибайт равен 1 048 576 байтам. |

Тело читается по частям через `for await...of`, поэтому большой файл можно измерить без сохранения на диск или загрузки в память целиком. Время включает ожидание ответа сервера. Для маленькой картинки это ожидание может занимать большую часть запроса.

При статусе вне диапазона 2xx, обрыве соединения или бездействии сокета в течение 30 секунд скрипт выводит ошибку и завершается с кодом 1. Для ссылки с перенаправлением укажите конечный URL файла.

## Что проверяют тесты

1. На десяти ответах разного размера сервер отправляет последнюю часть с задержкой. Тест проверяет порядок GET, полный объём, среднее время и формулу скорости.
2. Для gzip-ответа учитывается размер сжатого тела.
3. Десять пустых ответов HTTP 204 дают нулевой объём и нулевую скорость.
4. Неверный URL, неподдерживаемая схема и неверное число аргументов приводят к ошибке.
5. При HTTP 404 в середине серии скрипт останавливается на этом запросе.
6. При обрыве соединения частично скачанное тело приводит к ошибке.
7. При HTTP 302 скрипт останавливается до перехода по ссылке.

## Проверка на GitHub

Откройте **Actions → Тесты → Run workflow**, выберите ветку и нажмите **Run workflow**. В открывшемся запуске выберите задание для нужной версии Node.js. Шаг **Версия Node.js** показывает точный номер, а **Тесты CLI** — результаты и вывод измерения. Для ручного запуска файл `.github/workflows/tests.yml` должен быть в основной ветке и в репозитории должны быть включены Actions. [Открыть тесты на GitHub](https://github.com/Serezjjja/download-speed-cli/actions/workflows/tests.yml)

При пуше и pull request GitHub запускает ту же команду `node --test` на Linux. Матрица включает последнюю версию ветки 22.x, текущую LTS и свежий релиз, который выбирает `actions/setup-node` по метке `latest`.

## Проверенные версии Node.js

20 ноября 2026 года на Windows все семь тестов прошли на **22.23.2**, **26.13.1 LTS** и **27.0.0-alpha.0.1.1**. На эту дату 26.13.1 была самой свежей стабильной версией, а 27.0.0-alpha.0.1.1 — последней предварительной сборкой в каталоге релизов. Проверить установленную версию можно командой `node --version`.
